# Track Geometry Engine

A railway track geometry viewer and annotation tool. Load raw CSV traces from file or directly from CDDS, view all geometry channels interactively, and export annotated PDFs with fault and quality overlays.

---

## Requirements

This app includes a **portable version of Node.js** in the `node\` folder — no installation is required. Just follow the setup steps below.

---

## Files in This Folder

| File / Folder | Purpose |
|---------------|---------|
| `node\` | Portable Node.js — no installation needed |
| `node_modules\` | App dependencies — generated by `npm install` |
| `server.ts` | Backend server — handles all data processing and CDDS fetching |
| `index.html` | Frontend viewer — runs in the browser |
| `package.json` | Defines dependencies and run scripts |
| `tsconfig.json` | TypeScript configuration |
| `scData.json` | S&C asset database |
| `structuresData.json` | Bridges, culverts and level crossings database |
| `otmData.json` | OTM plan data |
| `drainageData.json` | Drainage asset data |
| `cdds_export.html` | Standalone CDDS CSV export tool |
| `convert_otm_to_json.js` | Script to refresh OTM data from an Excel file |
| `start.bat` | One-click launcher (double-click to start the app) |
| `.env` | Environment configuration (do not share or commit) |

## Network Requirements

> **Important — read this before installing or running the app.**

Different actions require different network connections:

| Action | Network Required |
|--------|-----------------|
| Installing node modules (`npm install`) | **102 WiFi** |
| Running the app (`npm run dev`) | Ethernet or **14 WiFi** |
| Loading a CDDS trace | Ethernet or **14 WiFi** (needs corporate network access) |
| Loading a local CSV file | Any connection (or none) |

If `npm install` fails or hangs, check you are connected to **102 WiFi** first.
After installation is complete, switch back to **Ethernet or 14 WiFi** before starting the server.

## First Time Setup

Before using the app for the first time you need to install the node modules.

1. **Connect to 102 WiFi**

2. Double-click `start.bat` — it will detect that `node_modules` is missing and run `npm install` automatically

3. When prompted, confirm you are on **102 WiFi** and press any key to continue

4. Once installation is complete, **switch back to Ethernet or 14 WiFi** when prompted, then press any key

5. The server will start and your browser will open automatically

> You only need to do this once. After the first run, `start.bat` will start the server directly without installing anything.

## Running the App

You can start the app in two ways:

## Running on Azure

This repo is now set up to run on **Azure App Service** as a Node.js app.

### What Azure needs

1. Create an **Azure Web App** for Node.js on Linux
2. Set the startup command to:
   ```
   npm start
   ```
3. Add the GitHub repository publish profile secret used by the workflow:
   - `AZUREAPPSERVICE_PUBLISHPROFILE_3F2E74FECAF741EDBAF59F8CC2311645`
4. Ensure the app setting `WEBSITE_NODE_DEFAULT_VERSION` is set to **20-lts** or another Node 20 runtime

### How deployment works

- `npm run build` compiles `server.ts` into `dist\server.js`
- Azure starts the app with `npm start`
- The Express server serves `index.html`, `cdds_export.html`, and the JSON asset files directly
- The GitHub Actions workflow deploys the compiled server plus the required static/data files

### Important limitation

CDDS access will only work in Azure if the Azure-hosted app can reach the same internal Network Rail services your local machine can reach today. If CDDS is only available on the corporate network, you will need Azure network connectivity such as:

- VPN or ExpressRoute into the corporate network
- VNet integration plus routing to the internal CDDS endpoint
- Firewall / DNS rules that allow the Web App to reach CDDS

Without that network path, **local CSV upload and PDF export will work**, but **live CDDS fetches will fail**.

## Using the App

### Loading a Trace

You can load a trace in two ways:

**From a local CSV file**
1. Click **Select file** next to Raw Data CSV
2. Optionally load a Faults CSV and Quality CSV
3. The trace will load automatically

**From CDDS**
1. Click the **Search** button in the Input Files panel
2. Enter the ELR, Track ID, and mileage range
3. Click **Find Available Dates** and select a survey date
4. Click **Load Trace** — the trace will fetch directly from CDDS
5. Once loaded, click **Download CSV** to save a local copy

---

### Exporting an Annotated PDF

1. Load a trace and optionally a Faults CSV and Quality CSV
2. Enter an output filename (optional)
3. Click **Export PDF**
4. The annotated PDF will download automatically

## What Gets Annotated on the PDF

| Annotation | Colour | Description |
|------------|--------|-------------|
| Reportable faults | Pink | Boxes at the fault position |
| Very Poor quality | Red | Boxes at the parameter row |
| Super Red quality | Cyan | Boxes at the parameter row |
| Poor quality | Blue | Boxes at the parameter row |
| S&C assets | Green | Vertical lines at asset mileage |
| OTM plan items | Coloured boxes | Planned maintenance locations |
| Structures | Purple dashed | Bridges, culverts, level crossings |

## Troubleshooting

| Problem | Fix |
|---------|-----|
| `npm install` hangs or fails | Make sure you are connected to **102 WiFi** |
| CDDS trace fails to load (502 error) | Make sure you are on **Ethernet or 14 WiFi** — CDDS requires the corporate network |
| Page not found at localhost:3000 | Make sure the terminal is still open and the server is running |
| No S&C or structure annotations | Check the ELR and Track ID in the CSV header match the database |
| `npm run dev` starts but immediately errors | Check the `.env` file exists in the app folder |
| Processing failed on PDF export | Check the Faults and Quality CSVs have the correct headers |
| `node` command not recognised in CMD | Run `set PATH=%CD%\node;%PATH%` first, or use `start.bat` which does this automatically |
